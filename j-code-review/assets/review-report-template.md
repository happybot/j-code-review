# 审查报告模板

按 `SKILL.md` 的「输出格式」填写。字段顺序固定，不增删标题。快速扫描模式只填第 1、2、4、8 节，并在第 2 节注明「快速扫描」。

## 1. 结论

- 结论：批准（含附带评论） / 需修改后批准 / 拒绝
- 一句话依据：
- 阻断项：P0 __ 条，P1 __ 条
- 非阻断项：P2 __ 条，P3 __ 条

结论只能三选一。第一行就写结论，不先铺垫。

## 2. 审查对象与范围

- 审查对象：
- 基线：
- 变更规模：__ 个文件，+__ / -__
- 审查模式：快速扫描 / 标准审查 / 发布前全量
- 专项规则：语言热点 / 测试质量 / 安全快速检查（已加载 / 不适用，说明原因）
- 已读范围：
- 未读范围：
- 跳过项：生成代码 / vendored 代码 / 其他

## 3. 变更判定（结论依据）

- 改动意图：
- 服务的用户：终端用户 / 未来读代码的开发者
- 整体效果：变好 / 不变 / 变差
- 本次引入的问题：
- 基线已有的问题（不计入本次）：

## 4. 发现

按 P0 → P1 → P2 → P3 排列。同一级别内，按结构、简化、复杂度、契约、文件大小、可读性排序。没有发现的级别写「无」。

### P0-1 · 标题

- 位置：`文件:行号`
- 为什么是恶化：违反了哪条维度，会导致什么后果
- 证据：
- 证据强度：`代码证据` / `测试证据` / `推测`
- 改法方向：改成什么样
- 评论前缀：无 / `Nit:` / `Optional:` / `FYI:`

## 6. 反对理由与证据强度

下结论前必须填。

- 反对当前结论的最强理由（最多 3 条）：
  1. 理由 / 证据强度 / 是否成立
  2. 理由 / 证据强度 / 是否成立
  3. 理由 / 证据强度 / 是否成立

批准时，这里列「不应合并」的理由；拒绝时，这里列「可以接受」的理由。存在带 `代码证据` 的 P0/P1 时，不得批准。

## 8. 验证与搜索空间

四种状态如实填写。没跑过就写未实测。

- 已运行并通过：
- 未实测：

- 无法验证：
- 未审维度：
- 未审文件：

## 快速扫描简版

只保留以下字段：

- 结论
- 审查对象与范围（注明「快速扫描」）
- 发现（只列 P0/P1 与明显结构问题）
- 验证与搜索空间

## 禁止项

- 不写「建议优化」这类没有方向的建议。
- 不写没有位置的问题。
- 不把口头解释当澄清。
- 不声称「测试已验证」，除非真的运行过并写进第 8 节。
- 不用 `Nit:` 淹没结构问题。
